# 7일의 마법서 (7 Days of Spellbook)

**상태**: 🔬 researching  
**생성일**: 2026-02-22  
**분류**: games  
**목표**: 프로토타입 — 핵심 재미 검증

## 개요

> **7일 동안 미친 마법 조합을 실험해서, 마지막 날 보스를 농락하는 코옵 로그라이크.**

| 항목 | 내용 |
|------|------|
| **장르** | 협동(Co-op) 로그라이크 액션 |
| **인원** | 2~4인 멀티플레이 |
| **플랫폼** | PC (Steam) |
| **1런 시간** | 약 70~100분 (하루 10~15분 × 7일) |
| **핵심 한 줄** | 7일 안에 랜덤 마법서로 빌드를 완성하고, 마지막 날 보스를 처치하라 |

## 핵심 게임 루프

```
아침: 던전 선택 → 낮: 던전 탐색 → 귀환: 보상 정산 → 밤: 성장/준비
                    ×6일 반복
                 → 7일차: 보스전
```

### 하루 사이클

1. **아침** — 파티 구성, 오늘 갈 던전 선택 (난이도/속성/보상 확인), "오늘의 세계 룰" 발표
2. **낮 (던전 탐색)** — 랜덤 룸 탐색, 마법서/재화 수집, 계약 NPC 만남, 적/엘리트 전투
3. **귀환** — 생존 인원 기준 보상 정산, 사망 시 디버프 부여
4. **밤** — 레벨업, 마법서 장착/합성, 보스 힌트 정리, 다음 날 전략 논의

## 오리지널 차별화 포인트 (3가지)

### 1. 7일 카운트다운 구조

기존 코옵 호러(Lethal Company, R.E.P.O.)는 "할당량 무한 반복" 루프지만, 이 게임은 **7일 끝에 보스전이라는 명확한 종착점**이 있다. 날이 지날수록 압박이 커지고, "준비가 충분한가?" 라는 긴장감이 자연스럽게 생긴다.

### 2. 공용 마법서 쟁탈

파티에 **공용 대마법서 1권**이 있고, 모든 마법은 여기 장착된다. 각 플레이어는 슬롯을 나눠 쓰는 구조. 좋은 마법서가 나오면 **누가 가져갈지 파티가 실시간 협상**해야 한다. PvE 안에서 사회적 긴장감이 생기는, 기존 협동 게임에 없던 갈등 축.

### 3. 보스가 "학습"한다

7일 동안 플레이어들이 많이 쓴 마법/속성을 보스가 기록. 보스전에서 **자주 쓴 패턴에 카운터 등장**. 같은 마법만 반복하면 마지막에 박살나고, 일부러 패턴을 숨기거나 "연습용/진짜" 마법을 나눠 쓰는 심리전이 가능.

## 마법서 시스템

### 구조

- 사람당 **3슬롯**, 파티 공용 대마법서 **4슬롯** → 총 최대 16스킬 (4인 기준)
- 마법 **5타입**: 공격 / 방어 / 제어(슬로우, 스턴) / 이동 / 유틸(시야, 루팅, 힌트)
- 각 마법마다 **한 줄짜리 특이 규칙**: "아군도 맞음", "맞추면 연쇄", "죽이면 쿨초기화" 등

### 획득 경로

| 경로 | 설명 | 차용 |
|------|------|------|
| **던전 드랍** | 룸 클리어, 엘리트, 숨겨진 상자에서 3개 중 1개 선택 | Slay the Spire |
| **상점** | 특정 속성/계열 확정 구매 (비쌈) | — |
| **계약 보상** | 조건 달성 시 희귀 마법서 지급 | Inscryption |
| **합성** | 하위 마법서 2~3개 희생 → 상위 마법서 | Inscryption |

### 파티 콤보 예시

- 얼음 마법으로 적 속도 저하 → 번개가 동결 상태 추가 피해
- 바람 마법으로 적 밀치기 → 불 마법의 장판 위로 이동
- 제어 마법으로 고정 → 모든 원거리 딜러가 일제 사격

## 던전 선택 시스템

매일 아침 2~3개 던전이 뜨고, 파티가 투표로 선택.

| 던전 타입 | 목적 | 리스크 |
|-----------|------|--------|
| **루팅 던전** | 마법서, 재화 수집 | 낮음 |
| **정보 던전** | 보스 약점, 패턴 힌트 | 중간 |
| **도박 던전** | 희귀 마법서, 계약 | 높음 (사망 위험 상승) |

→ **"오늘은 돈인가, 정보인가, 도박인가"** 선택이 매일의 핵심 고민.

---

## "오늘의 세계 룰" 시스템

매일 아침 랜덤으로 1~2개 세계 룰이 발표된다. 단순하지만 마법서와 합쳐지면 예측 불가능한 상황 발생.

### 예시 룰 카드

| 룰 | 효과 |
|----|------|
| 마법 폭주 | 모든 마법 위력 2배, 시전자도 피해 입음 |
| 슬롯 셔플 | 아침에 모든 마법서 슬롯 랜덤 재배치 |
| 유령의 날 | 사망 시 유령 상태로 정찰만 가능 (소멸 대신) |
| 소리의 법칙 | 마법 시전 시 목소리를 질러야 위력 상승 (YAP YAP식) |
| 역류 | 힐 마법이 데미지, 데미지 마법이 힐 |
| 마나 폭풍 | 쿨타임 50% 감소, 적도 마법 사용 |
| 침묵의 밤 | 음성 채팅 비활성화, 핑/이모트로만 소통 |
| 중력 반전 | 점프 높이 3배, 낙하 데미지 3배 |

→ **마법서 빌드 × 오늘의 룰 = 매일 다른 경험**

---

## 계약 시스템

던전 중간에 나오는 악마/정령과의 계약. **파티 투표로 결정** — 다수결이지만 결과는 전원에게 영향.

### 예시 계약 카드

| 계약 | 대가 | 보상 |
|------|------|------|
| 시간의 거래 | 남은 일수 1일 삭감 | 전설 마법서 즉시 지급 |
| 보스의 축복 | 보스 10% 강화 | 오늘 보상 2배 |
| 침묵의 대가 | 랜덤 1명 다음 날 마법 사용 불가 | 전원 최대 체력 +30% |
| 희생의 제단 | 마법서 1권 영구 소멸 | 나머지 마법서 전부 1단계 업그레이드 |
| 도박사의 주사위 | 50% 확률로 전원 체력 절반 | 50% 확률로 희귀 마법서 2권 |
| 유령의 계약 | 다음 사망 시 부활 불가 | 현재 체력 전회복 + 공격력 2배 |

→ **"야 이거 받자 VS 미쳤냐" 파티 내 논쟁이 핵심 재미**

## 7일 타임라인

| 일차 | 테마 | 콘텐츠 |
|------|------|--------|
| 1~2일 | 맛보기 | 기본 마법 수집, 쉬운 던전, 튜토리얼 계약 |
| 3~4일 | 본격 빌드 | 미니보스 등장, 보스 패턴 일부 노출, 위험 계약 러시 |
| 5~6일 | 최후 준비 | 보스 전용 "준비 던전" 개방, 합성/계약 마지막 기회, 정보 정리 |

## 보스전 설계

### 보스 학습 메커니즘

- 7일간 플레이어가 가장 많이 쓴 마법 타입 **TOP 2를 보스가 기록**
- 보스전에서 해당 타입에 **카운터 패턴 발동**:
  - 번개 많이 썼으면 → 번개 반사 방벽
  - 불 많이 썼으면 → 불 흡수 + 화염 반격
- 같은 빌드만 고집하면 마지막에 박살 → 의도적 패턴 분산 또는 "페이크 빌드" 운영하는 심리전

### 보스전 구조

- **다단계 페이즈**: 1페이즈에서 파악한 정보로 2페이즈 대응
- **준비도 반영**: 정보 던전에서 모은 힌트 수에 따라 약점 노출도 변화
- **환경 조작**: 전장 오브젝트를 마법으로 조작하여 유리한 지형 만들기
- **보스 로테이션**: 매 런마다 최종 보스 종류가 달라짐

## "친구들이랑 하면 터지는" 순간 설계

이 게임의 목표는 **"썰 풀기 좋은 순간들"**을 많이 만드는 것.

- 오늘의 룰 "점프할 때마다 랜덤 마법 발동" + 절벽 옆에서 점프 → 자기 발밑에 폭발 소환 → 전원 추락
- 계약 "보상 두 배, 대신 한 명 마비" → 딜러가 마비 걸림 → "왜 아까 힐러한테 양보 안 했냐"
- 보스전에서 평소 애용하던 번개 썼더니 보스가 복사해서 되쏨 → 전멸 → 다음 런에서 완전 다른 빌드로 복수

## 아이디어 분석

### 강점

- **명확한 긴장감 곡선**: 7일 카운트다운 → 날마다 압박 증가 → 무한 루프가 아닌 종착점이 있는 런
- **오리지널 메커닉**: 보스 학습, 공용 마법서 쟁탈 — 레퍼런스 게임들에 없는 차별화 요소
- **사회적 재미**: PvE 안에서 협상/투표/희생 드라마 — 스트리머 콘텐츠에도 적합
- **높은 리플레이성**: 랜덤 마법서 × 세계 룰 × 계약 × 보스 로테이션 = 매 런이 다름

### 리스크와 대응

| 리스크 | 설명 | 대응 방안 |
|--------|------|-----------|
| **세션 길이** | 7일 런 = 최소 70분+ → 캐주얼 접근 어려움 | 하루 = 10~15분으로 제한, "저장 후 이어하기" 지원, 빠른 모드(3일) 옵션 |
| **보스 학습 밸런스** | 자주 쓴 마법 카운터 → "준비가 무의미" 느낌 | 완전 면역이 아닌 내성(데미지 30% 감소) 수준, TOP 2만 카운터 |
| **공용 마법서 독성** | 협상 실패 → 트롤링, 독점 | 투표 시스템, 라운드 로빈 우선권, 기여도 기반 우선순위 |
| **밸런스 복잡도** | 마법 × 룰 × 계약 조합 폭발 | MVP에서 소수(마법 15, 룰 8, 계약 6)로 시작, 데이터 기반 확장 |
| **멀티플레이어 기술** | 네트워크 동기화, 지연 처리 | 서버-권위(server-authoritative) 아키텍처, netfox 애드온 활용 |

| **Spellmasons** | 코옵 마법 로그라이크 | 우리는 실시간 액션 + 7일 압박, Spellmasons는 턴제 |
| **4Loop** (Bad Robot) | 코옵 로그라이크 슈터 | 우리는 마법 조합/공유 + 보스 적응, 4Loop은 총기 기반 |
| **Deep Rock Galactic** | 코옵 PvE, 미션 선택 | 우리는 로그라이크 런 구조 + 마법 빌드 초점 |

### 추가 아이디어 후보

- **"예언자" 역할**: 매일 밤 보스 관련 단편적 힌트 → 파티원들이 조각을 맞춰 보스 약점 추론
- **관전자/유령 모드**: 사망 플레이어가 유령으로 제한적 지원 (시야 공유, 함정 알림) → 죽어도 지루하지 않음
- **"카르마" 시스템**: 계약에서 이기적 선택을 많이 하면 악마가 더 강한 계약을 제시, 협동적 선택 시 정령이 버프 제공

### 핵심 기술 요구사항

| 요구사항 | 구현 난이도 | 비고 |
|----------|-------------|------|

| 마법 조합 시스템 | 중간 | 데이터 드리븐 설계로 확장성 확보 |
| AI 보스 (적응형) | 중간~높음 | 플레이어 행동 추적 + 패턴 선택 로직 |
| 음성 채팅 (근접) | 높음 | 외부 SDK 필요 (Vivox, Discord SDK 등) |
| 세이브/로드 | 낮음 | 런 상태 직렬화 |
| UI (마법서 관리, 투표) | 낮음~중간 | 드래그앤드롭, 실시간 동기화 |

### 엔진 비교 (이 게임 기준)

|  | UE5 | Unity | Godot 4 |
|--|-----|-------|---------|
| **학습 곡선** | 높음 (C++/Blueprint) | 중간 (C#) | 낮음 (GDScript ≈ Python) |
| **멀티플레이어** | 내장 Replication (강력) | Netcode for GameObjects, Mirror, Fish-Net | 내장 ENet + RPC, netfox 애드온 |
| **프로토타입 속도** | 느림 (빌드 시간 김) | 보통 | 빠름 (20MB 에디터, 핫 리로드) |
| **3D 품질** | 최상 (Nanite, Lumen) | 좋음 (URP/HDRP) | 보통 (개선 중) |
| **2D 지원** | 약함 | 좋음 | 좋음 |
| **에셋 스토어** | 중간 | 최대 | 작음 (급성장 중) |
| **비용** | 무료 (로열티 5%) | 무료 (조건부 런타임 비용) | 완전 무료, 오픈소스 |
| **사용자 친숙도** | 에디터 스크립팅 경험 있음 | 없음 | GDScript ≈ Python (강점) |
| **커뮤니티** | 대규모 | 대규모 | 중간 (급성장) |
| **인디 코옵 사례** | 적음 | 많음 | 증가 중 |

### 엔진 추천: Godot 4

**프로토타입 단계에서 Godot 4를 선택하는 이유:**

1. **GDScript ≈ Python** — Python 개발 경험을 직접 활용 가능, 학습 곡선 최소
2. **프로토타입 반복 속도** — 20MB 에디터, 핫 리로드, 빠른 빌드
3. **내장 멀티플레이어** — ENet, RPC, 동기화 내장, netfox 애드온으로 보완
4. **완전 무료** — 오픈소스, 로열티 없음, 런타임 비용 없음
5. **충분한 학습 자료** — Godot 4 코옵 멀티플레이어 과정 (18시간+), 로그라이크 예제 프로젝트 다수
6. **전환 가능** — 프로토타입에서 핵심 재미 검증 후, 3D 고품질이 필요하면 UE5로 전환 가능

**Godot 4 멀티플레이어 스택:**

```
게임 클라이언트 (Godot 4)
├── 네트워킹: ENet (내장) + netfox (애드온)
│   ├── RPC (Remote Procedure Call)
│   ├── MultiplayerSynchronizer (자동 동기화)
│   └── MultiplayerSpawner (오브젝트 생성)
├── 음성 채팅: GDExtension + Opus 코덱 (또는 외부 SDK)
├── 던전 생성: 커스텀 BSP / WFC 알고리즘
└── 서버: Dedicated (Linux) 또는 P2P (프로토타입)
```

## 잡스의 교훈: "아이디어의 병" 경계

> "훌륭한 아이디어가 일의 90%라고 생각하는 병. 아이디어와 제품 사이에는 엄청난 양의 장인정신이 존재한다."
> — Steve Jobs, 1995

이 기획서 자체가 470줄이지만, **플레이 가능한 시간은 아직 0초**다.
아이디어는 출발점이지 목적지가 아니다. 아래 로드맵은 **"가장 빨리 플레이해볼 수 있는 것"** 순서로 재구성했다.

### 최소 재미 단위 (Minimum Unit of Fun)

모든 시스템을 만들기 전에, **이것 하나만 먼저 검증**:

```
1명, 1개 방, 3~4종 마법, 5~8마리 적
→ "스펠 조합이 재미있는가?" 만 확인
```

7일 구조, 보스 학습, 계약, 세계 룰은 전부 "프레이밍"이다.
**핵심 재미는 "마법 조합이 즉시 만족감을 주는가"** — 이게 안 되면 나머지는 의미 없다.

### 시스템 우선순위

| 순위 | 시스템 | 분류 | 이유 |
|------|--------|------|------|
| 1 | 스펠 조합/시너지 | **필수** | 게임의 핵심. 없으면 다른 게임 |
| 2 | Game Feel (screen shake, hit pause) | **필수** | 구현 쉬움, 체감 개선 극대화 |
| 3 | 간단한 전투 (적 AI) | **필수** | 마법을 써볼 대상 필요 |
| 4 | 2인 협동 | **필수** | 코옵 게임이므로 |
| 5 | 공용 마법서 쟁탈 | **필수** | 핵심 차별화 포인트 |
| 6 | 1일 사이클 | 필수 | 루프의 최소 단위 |
| 7 | 보스전 | 필수 | 목표가 있어야 긴장감 |
| 8 | 보스 학습 | 부가 | 단순 보스로 먼저 검증 |
| 9 | 7일 구조 | 부가 | 1일로도 루프 검증 가능 |
| 10 | 세계 룰 / 계약 | 부가 | 나중에 추가 |
| 11 | 절차적 던전 | 부가 | 손제작 1~2방으로 충분 |
| 12 | 근접 음성 / 메타 해금 | 부가 | 후순위 |

## 개발 로드맵 (수정: 재미 검증 우선)

### Phase 0: 기획 완성 (완료)

- [x] idea-vault에 아이디어 문서 저장
- [x] 아이디어 분석 + 보완
- [x] 엔진 비교 + 선택
- [x] 딥다이브 리서치 (멀티플레이어, 던전 생성, 재미 분석)
- [x] 잡스의 교훈 적용 → 로드맵 재구성

### Phase 1: "1룸 스펠 콤보" (1주) — 최소 재미 검증

**목표: 마법 조합이 재미있는지 확인**

- 싱글플레이어로 시작 (멀티는 아직 안 붙임)
- 손제작 1개 방 + 간단한 적 5~8마리
- 마법 3~4종 (공격 2, 제어 1, 이동 1)
- 콤보: 얼음(슬로우) → 번개(추가 피해) 같은 시너지 1~2개
- Game Feel: screen shake + hit pause (2~3프레임) + 기본 파티클
- **검증 질문**: "이거 쏘는 게 기분 좋은가? 콤보가 만족스러운가?"

### Phase 2: 로컬 코옵 + 공용 마법서 (1~2주)

**목표: 협동이 재미를 더하는지 확인**

- 로컬 2인 (같은 PC, 스플릿 스크린 또는 같은 화면)
- 공용 마법서 슬롯: "이 마법 누가 쓸래?" 선택
- 적 수/난이도 조정 (2인 기준)
- 사망/부활: 20초 내 부활 또는 고스트 참여
- **검증 질문**: "친구랑 하니까 더 재밌는가? 마법서 나눠 쓰는 게 긴장감인가?"

### Phase 3: 온라인 멀티 + 던전 루프 (2~3주)

**재미가 검증된 후에만 진행**

- ENet 기반 온라인 멀티 (2~4인)
- 간단한 던전 생성 (Random Rooms + Corridors, 시드 동기화)
- 1일 사이클: 던전 → 보상 → 마법서 선택
- 기본 보스 1종 (패턴 2~3개, 학습 없이)

### Phase 4: 7일 구조 + 학습 AI + 폴리시

**핵심 루프가 재밌으면 확장**

- 7일 카운트다운
- 보스 학습 (자주 쓴 마법 TOP 2 카운터)
- 세계 룰 카드 5종
- 계약 카드 5종
- 메타 해금, 난이도 단계

### 이후: 제품화 판단

- 프로토타입 반응이 좋으면 → 엔진 유지 또는 UE5 전환 결정
- 아트 스타일 확정 (2D 탑다운 vs 3D)
- 스팀 스토어 페이지 + 위시리스트 수집
- 얼리 액세스 로드맵
